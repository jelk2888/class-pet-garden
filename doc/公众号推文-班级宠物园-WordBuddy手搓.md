# 班级积分也能养宠？我用 WordBuddy 手搓了一套「班级宠物园」

老师最烦什么？

不是备课，是积分表。

Excel 记分记到眼花，小红花贴到墙皮发皱，学期末一对账——漏了谁、多了谁，全班吵成一锅粥。更别提学生眼里那句：「老师，加分到底有什么用啊？」

积分如果只是数字，确实没劲。

但如果积分能喂活一只宠物呢？

这就是「东郭工作室·班级宠物园」想干的事：把课堂评价，做成一场全班一起玩的养成游戏。这套系统，是我**用 WordBuddy 手搓**出来的教师向工具——不是概念稿，是能直接开班用的。

---

## 它到底是什么

一句话：

**班级积分管理 + 电子宠物养成。**

老师在课堂上随手加减分，学生的宠物跟着涨经验、换形态、冲排行。做得好能毕业拿徽章，扣狠了宠物还会「受伤」——规矩还在，只是反馈不再冷冰冰。

面向谁？中小学班主任、任课老师，尤其是想少扯皮、多点正向反馈的课堂。

游客也能先进去逛一圈演示班；注册登录后，多班级、规则自定义、备份这些正经功能才完全打开。

---

## 课堂上真正用得上的几块

**宠物教室**  
学生卡片铺开，点人、选规则、加分扣分。批量评价也有，适合早读后那波集中表扬。

**九级养成（从蛋到传说）**  
不是「有个图标」就算养宠。从 0 级蛋形态，一路到满级传说，背景和形象跟着变。积分够了自然升级，学生看得见自己的努力长什么样。

**评价规则可增可删**  
学习、行为、健康、其他——内置一长串常用项，也能自己加「举手发言 +1」「作业潦草 -1」。规则不是死的，跟着班风走。

**一组一宠**  
小组共用一只宠、攒集体能量。个人分和个人宠分开记，适合合作任务、组间竞赛。

**老师工具箱**  
随机点名、课堂计时、表格粘贴批量记分、排行榜、小卖部兑换、成长记录撤销……课堂里零碎但高频的动作，收在一个入口。

**图鉴 · 荣誉 · 备份**  
图鉴看全形态；毕业有徽章墙；数据可导出备份。换电脑、换学期，不至于一切归零。

技术上它是网页系统：浏览器打开就能用，数据落在本地 SQLite，也能丢到自己的服务器或群晖上跑。老师不必懂代码，会点链接就行。

## 为什么值得一试

积分制度失败，常常不是因为规则写得差，而是因为：

- 反馈太慢（周末才统计）
- 反馈太抽象（就一个总分）
- 反馈不可见（学生不知道自己卡在哪）

宠物园把「规则 → 即时反馈 → 可见成长」串起来。孩子在意的是「我的宠今天有没有长大」；老师在意的是「这一下加减分有没有记上、能不能改」。两边需求对上了，制度才站得住。

当然它不是万能的。课堂秩序仍靠人，工具只是放大器。你愿意坚持用两周，它才像工具；只用一天新鲜感，它就只是个玩具。

下面这段**不是本系统的制作流水账**，而是：你换 Claude、GPT、Gemini、通义、文心、Kimi 等大模型时，可以直接丢过去的「总需求提示词」。复制、按需改校名和学段即可。

### 总提示词（推荐整段粘贴）

```text
请帮我设计并实现一个面向中小学教师的「班级宠物园」Web 系统（可本地运行）。

【产品目标】
把班级积分评价与电子宠物养成结合：老师课堂加减分 → 学生宠物获得经验并升级 → 可见排行与荣誉。

【角色】
- 游客：可浏览演示班，功能受限（如不可删班）
- 注册教师：完整功能（多班级、学生、评价、规则、备份等）
- 管理员：用户与图鉴等后台能力

【核心功能】
1. 多班级管理：创建/切换班级；游客不可删除班级
2. 学生管理：添加、批量导入、学号、标签
3. 宠物养成：
   - 每人可领养一只宠物
   - 等级 0～8（0=蛋，8=传说满级），每级有独立形象与背景
   - 经验与积分关联，自动计算等级与进度
   - 积分过低可进入受伤/阵亡状态，支持复活任务（可开关）
4. 课堂评价：
   - 单人/批量加减分
   - 规则分类：学习/行为/健康/其他
   - 教师可自行增加、编辑、删除规则；支持导入规则包
   - 评价记录可查询、可撤销（限近期）
5. 一组一宠：小组共同宠物与集体能量，与个人积分分离
6. 工具箱：随机点名、计时器、表格粘贴批量记分、排行榜入口
7. 小卖部：积分兑换班级特权（可配置商品显示/隐藏）
8. 图鉴、荣誉徽章墙、留言板（游客只读）
9. 数据：SQLite 持久化；支持备份导出/导入；可配置数据目录便于 NAS 部署

【界面要求】
- 中文界面，适合投影仪/教室大屏与笔记本
- 宠物教室首页以学生卡片为主，操作路径短
- 移动端基本可用

【技术偏好（可调整）】
- 前端：Vue 3 + Vite + TypeScript
- 后端：Node.js + Express
- 数据库：SQLite（如 better-sqlite3）
- 前后端可同端口生产部署：API + 静态页面 + 宠物图片

【交付】
- 可运行的完整项目结构
- README：如何安装、启动、默认账号
- 不要只写概念说明，请给出可落地的代码与目录

请先给出信息架构与数据表设计，再分模块实现。
```

### 想拆开问时，可以用的短提示词

**只要产品说明（给非技术同事看）：**

```text
请用通俗中文介绍一款「班级积分 + 电子宠物养成」教师工具：解决什么问题、有哪些模块、课堂一天怎么用、注意事项。不要写开发步骤。
```

**只要规则与等级设计：**

```text
为小学/初中课堂设计一套加减分规则（学习/行为/纪律/卫生），以及宠物 0～8 级成长阈值与称号命名。输出表格，便于直接配置进系统。
```

**只要部署到群晖/自己的电脑：**

```text
我有一个 Vue+Express+SQLite 的班级宠物系统。请给出 Windows 本地一键启动，以及群晖 Node.js + 反向代理 + 数据目录（DATA_DIR）的部署说明。强调 SQLite 不要放在只读 Web 目录。
```

换模型时注意三点：说清「可运行、别只聊天」；约束学段和中文；把「游客/教师/管理员」权限边界写死，否则容易做成谁都能乱删班的玩具站。

## 写在最后

积分制度不缺表格，缺的是学生愿意抬头看一眼的理由。

「班级宠物园」把理由变成一只会长大的宠。你可以用现成的思路自己做，也可以像我一样——**用 WordBuddy 手搓**一版，改成自己班的规矩、自己的宠物图鉴、自己的加减分清单。

工具会过时，但「让评价被看见」这件事，不会。

如果你也是天天和积分表较劲的老师，不妨先想清楚一件小事：

明天课堂上，你最想表扬的那个瞬间——加完分之后，孩子第一眼能看到什么？

看到数字，还是看到成长？
